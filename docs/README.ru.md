# Re:ZERO Loop

![](./images/rezero.webp)

> Re:ZERO Loop — это проект, вдохновлённый **Посмертным возвращением** из **Re:Zero. Жизнь с нуля в альтернативном мире**.

Для предотвращения деградации производительности ИИ, вызванной загрязнением накопленного контекста, появились такие техники, как Ralph Loop.  
Однако, даже если контекст поддерживается чистым, если накапливаемый код загрязняется, деградация производительности из-за кодовой базы неизбежна.

Re:ZERO Loop родился из идеи внедрить Посмертное возвращение в ИИ для преодоления этой проблемы.

## Установка

### Вариант 1: Скопировать напрямую в проект

```bash
mkdir -p scripts/rezero
cp /path/to/rezero/rezero.sh scripts/rezero/
cp -r /path/to/rezero/prompts scripts/rezero/prompts
chmod +x scripts/rezero/rezero.sh
```

### Вариант 2: Установить навыки глобально

```bash
cp -r skills/task ~/.claude/skills/
cp -r skills/rezero ~/.claude/skills/
cp -r skills/witches-tea-party ~/.claude/skills/
cp -r skills/rem ~/.claude/skills/
```

### Вариант 3: Использовать как плагин Claude Code

```bash
/plugin marketplace add epsilondelta-ai/rezero
/plugin install rezero-skills@rezero-marketplace
```

После установки доступны навыки `/task` и `/rezero`.

## Рабочий процесс

### 1. Создание определения задачи

Используйте навык task для определения пользовательской истории:

> «Загрузите навык task и создайте задачу для [описание функциональности]»

Результат: `task.json` (пользовательская история с приоритетами и критериями приёмки)

### 2. Запуск Re:ZERO Loop

```bash
./rezero.sh [max_iterations]                        # Claude (по умолчанию)
./rezero.sh --tool codex [max_iterations]           # OpenAI Codex
./rezero.sh --max-deaths 5 [max_iterations]         # Установить макс. Посмертных возвращений на историю
```

Итерации по умолчанию: 10, максимум смертей по умолчанию: 3

**Процесс выполнения:**

1. Создаёт ветку функциональности из `task.json`
2. Выбирает незавершённую историю с наивысшим приоритетом
3. Реализует историю
4. Чаепитие ведьм проводит оценку качества
5. При успехе: коммит и обновление статуса в `task.json`
6. При неудаче: срабатывает Посмертное возвращение, откат к контрольной точке
7. Записывает извлечённые уроки в `progress.txt`
8. Повторяет, пока все истории не будут завершены или не будет достигнут максимум итераций

## Концепции

### Нацуки Субару

Нацуки Субару — главный герой Re:Zero.

- В этом проекте агент, выполняющий работу, назван **Нацуки Субару**.
- Он не просто выполняет задачи, а накапливает знания через множественные Посмертные возвращения.
- Каждый раз разрабатывает оптимальный план для достижения цели.

### Посмертное возвращение

![Нацуки Субару](./images/subaru.webp)

Когда во время работы обнаруживается аномалия, или когда результаты неудовлетворительны даже после завершения, Нацуки Субару использует Посмертное возвращение для отката к контрольной точке.

- Если во время работы обнаруживается аномалия, работа останавливается, и используется Посмертное возвращение для отката к контрольной точке.
- Если Чаепитие ведьм определяет, что критерии успеха не выполнены, принудительно запускается Посмертное возвращение.
- Ключевое значение Посмертного возвращения в том, что возврат к контрольной точке происходит с сохранением воспоминаний о причинах неудачи.

### Чаепитие ведьм

![Чаепитие ведьм](./images/witches-tea-party.webp)

Фанаты, знакомые с оригинальным сеттингом, могут удивиться тому, что **Чаепитие ведьм** выступает в роли оценщика.  
Однако тот факт, что шесть ведьм обладают различными характерами, в сочетании с предположением, что Сателла может определять контрольные точки Субару, сделали эту роль очень подходящей для системы оценки.

- После завершения работы созывается «Чаепитие ведьм».
- Шесть ведьм оценивают работу с точки зрения своих перспектив.
- Сателла агрегирует оценки шести ведьм, чтобы определить, обновить контрольную точку или запустить Посмертное возвращение.

| Ведьма                    | Критерий оценки                                                                                                                                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Эхидна (Алчность)         | Исследовала ли эта реализация все возможности? Обработаны ли все граничные случаи? Является ли знание исчерпывающим? На практике: проверяет покрытие тестами, полноту API, документацию и обработку граничных условий.   |
| Минерва (Гнев)            | Действительно ли этот баг исправлен, или проблема просто перераспределена? Создаёт ли патч новые режимы отказа в несвязанных функциях? Запускает регрессионные тесты и проверяет, что исправление не ломает несвязанную функциональность. |
| Сехмет (Лень)             | Можно ли достичь того же результата с меньшими усилиями? Есть ли ненужная сложность? Проверяет алгоритмическую эффективность, избыточные вычисления и чрезмерную инженерию.                                           |
| Тифон (Гордость)          | Знает ли код свои грехи? Есть ли намеренно включённые антипаттерны? Нарушает ли он свои собственные принципы? Обнаруживает запахи кода, нарушения линтинга и признанный, но не исправленный технический долг.           |
| Дафна (Чревоугодие)       | Насколько голоден этот код? Оправдано ли потребление памяти/CPU/токенов? Проверяет использование памяти, количество вызовов API, размер бандла и потребление токенов.                                                   |
| Кармилла (Похоть)         | Удовлетворяет ли этот код то, что пользователь действительно хочет? Привлекателен ли UX, или за очарованием скрыты опасные дефекты? Оценивает эргономику API, сообщения об ошибках и соответствие заявленному намерению пользователя. |
| Сателла (Зависть)         | Финальный агрегатор. Определяет, что является «приемлемым результатом», агрегирует оценки шести ведьм с использованием взвешенных баллов и выносит вердикт жизни или смерти: прохождение контрольной точки или запуск Посмертного возвращения. |

### Рем

> **!!! ВНИМАНИЕ: СПОЙЛЕРЫ !!!**

![Рем](./images/rem.webp)

После сражения с Белым Китом имя и воспоминания Рем были поглощены Архиепископом Чревоугодия, и она впала в состояние анабиоза.  
Контрольная точка Посмертного возвращения зафиксировалась после того, как Рем впала в это состояние, сделав невозможным возврат дальше.  
При планировании Re:ZERO Loop осознание того, что существование Рем будет критически важным для этого проекта — что технический долг может оставаться даже после прохождения Чаепития ведьм — привело к включению Рем в проект.

- Даже после прохождения Чаепития ведьм, если остаётся технический долг или элементы, требующие будущих исправлений, они сохраняются при обновлении контрольной точки.
- Рем выявляет и отдельно записывает технический долг и элементы, нуждающиеся в исправлении.
- Если такие элементы существуют, Субару приоритизирует спасение Рем перед переходом к следующей задаче.
