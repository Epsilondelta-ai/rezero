# Re:ZERO Task Converter

This skill converts a markdown task document (generated by the Task Definition skill) into `task.json` format for the Re:ZERO Loop autonomous agent system.

## Input

A markdown task document from `tasks/task-[feature-name].md`.

## Output Structure

```json
{
  "name": "ProjectName",
  "branch": "rezero/feature-name",
  "description": "Brief description of the feature or change",
  "stories": [
    {
      "id": "US-001",
      "title": "Short descriptive title",
      "description": "Detailed description of what to implement",
      "criteria": [
        "First acceptance criterion",
        "Second acceptance criterion",
        "Typecheck passes"
      ],
      "priority": 1,
      "passes": false
    }
  ]
}
```

## Conversion Rules

### Story Extraction
- Extract each user story from the task document.
- Assign sequential IDs: `US-001`, `US-002`, etc.
- Pull acceptance criteria directly from the story's checklist items.
- Every story MUST include `"Typecheck passes"` as a criterion.
- UI-facing stories MUST include an **automated browser verification** criterion (E2E test), not a manual "Verify in browser" self-report. Use the format: `"E2E test: [what to verify]"`.

### Priority & Dependency Ordering
Assign priorities based on implementation dependency order:

1. **Database/schema changes** — Foundation must come first
2. **Backend logic & API endpoints** — Build on the data layer
3. **Shared utilities & types** — Common code before consumers
4. **UI components** — Visual layer last
5. **Integration & polish** — Final touches

Lower priority number = implement first.

### Right-Sizing Validation

Before finalizing, validate that each story is appropriately scoped for a single Re:ZERO Loop iteration (one agent context window):

**Appropriately sized**:
- Adding a database column or table
- Creating a single API endpoint
- Building one UI component
- Writing tests for one module
- Updating configuration or environment setup

**Too large — must be split**:
- "Build the entire feature" (split into data, logic, UI stories)
- "Refactor the authentication system" (split into specific refactor steps)
- "Add CRUD operations for a resource" (split into Create, Read, Update, Delete)

If a story is too large, split it into multiple stories and re-assign priorities.

### Branch Naming
- Use the pattern: `rezero/[feature-name]`
- Feature name in kebab-case
- Example: `rezero/task-priority-system`

## Process

1. Read the task document from the specified path.
2. Extract and validate all user stories.
3. Check right-sizing — split any oversized stories.
4. Assign dependency-based priorities.
5. Generate `task.json` at the project root.
6. If a previous `task.json` exists for a different feature:
   - Archive it to `tasks/archive/task-[old-feature]-[timestamp].json`
   - This preserves work history across features.

## Example

Given a task document for "Add task priority system":

```json
{
  "name": "MyApp",
  "branch": "rezero/task-priority",
  "description": "Add a priority system to tasks allowing users to set and filter by priority levels",
  "stories": [
    {
      "id": "US-001",
      "title": "Add priority field to database",
      "description": "Add a 'priority' column to the tasks table with enum values: 'high', 'medium', 'low'. Default value should be 'medium'.",
      "criteria": [
        "Migration creates priority column with correct type and default",
        "Existing rows default to 'medium'",
        "Typecheck passes"
      ],
      "priority": 1,
      "passes": false
    },
    {
      "id": "US-002",
      "title": "Add priority to task API endpoints",
      "description": "Update create and update endpoints to accept a priority field. Add validation for allowed values.",
      "criteria": [
        "POST /tasks accepts optional priority field",
        "PUT /tasks/:id accepts optional priority field",
        "Invalid priority values return 400 error",
        "Typecheck passes"
      ],
      "priority": 2,
      "passes": false
    },
    {
      "id": "US-003",
      "title": "Display priority badges on task cards",
      "description": "Show colored priority indicators on each task card: red for high, yellow for medium, gray for low.",
      "criteria": [
        "Priority badge visible on each task card",
        "Colors match specification (red/yellow/gray)",
        "E2E test: priority badges render with correct colors on task cards",
        "Typecheck passes"
      ],
      "priority": 3,
      "passes": false
    }
  ]
}
```
